================================================================================
DISEÑO Y SCRIPT DE BASE DE DATOS PARA SUPABASE (POSTGRESQL) - ANGEL JASHUIEL
================================================================================

Este documento contiene el diseño propuesto para la base de datos de tu tienda de
alquiler de ropa formal "Angel Jashiel" (Andahuaylas), listo para ser utilizado en
Supabase.

Supabase utiliza PostgreSQL, una base de datos relacional muy potente. En base a
tu código frontend actual, hemos estructurado dos tablas principales:
1. `catalog_items` (Inventario de ternos, vestidos y calzados)
2. `rental_leads` (Clientes interesados y consultas de alquiler)

A continuación encontrarás el diseño de las tablas, consejos técnicos de diseño,
el script SQL listo para copiar y pegar en Supabase (incluyendo datos iniciales) y
las políticas de seguridad necesarias (RLS).

--------------------------------------------------------------------------------
1. DISEÑO DE LAS TABLAS
--------------------------------------------------------------------------------

A. Tabla: `catalog_items` (Prendas de vestir)
---------------------------------------------
Esta tabla almacena la ropa y el calzado disponibles para alquiler.

* Campo: `id` (bigint / auto-incremental) -> Identificador único.
* Campo: `name` (varchar) -> Nombre de la prenda (ej. "Terno Negro Clásico").
* Campo: `category` (varchar) -> Categoría restringida a: 'ternos', 'vestidos', 'calzados'.
* Campo: `description` (text) -> Detalles de la prenda.
  Nota: Renombramos 'desc' a 'description' porque 'DESC' es una palabra reservada
  en SQL (usada para ordenamiento descendente). Usar 'description' te evitará
  errores de sintaxis al consultar la base de datos.
* Campo: `price` (numeric) -> El precio del alquiler (ej. 60.00).
  Nota: En tu frontend actual se almacena como texto ("S/. 60"). En base de datos,
  lo correcto es almacenarlo como tipo numérico (`numeric` o `decimal`) para
  poder realizar cálculos matemáticos en el dashboard (ej. sumar ingresos).
  La moneda (S/.) y formato se le da luego en el frontend.
* Campo: `duration` (varchar) -> Duración del cobro (ej. "por día").
* Campo: `img` (text) -> URL de la imagen de la prenda.
* Campo: `alt` (text) -> Texto alternativo para la imagen (accesibilidad).
* Campo: `available` (boolean) -> Indica si la prenda está libre (true) o alquilada (false).
* Campo: `sizes` (varchar) -> Tallas disponibles en formato de texto (ej. "S · M · L · XL").
* Campo: `created_at` (timestamptz) -> Fecha y hora automática de registro.

B. Tabla: `rental_leads` (Prospectos y consultas de alquiler)
-------------------------------------------------------------
Esta tabla registra a los clientes que solicitan información o reservan.

* Campo: `id` (bigint / auto-incremental) -> Identificador único de lead.
* Campo: `name` (varchar) -> Nombre completo del cliente.
* Campo: `phone` (varchar) -> Teléfono o número de WhatsApp del cliente.
* Campo: `event` (varchar) -> Tipo de evento, restringido a: 'boda', 'quince', 'graduacion', 'gala'.
* Campo: `date` (date) -> Fecha en que se realizará el evento del cliente.
* Campo: `status` (varchar) -> Estado del lead: 'Nuevo', 'Contactado', 'Confirmado', 'Cancelado'.
* Campo: `item_interest` (varchar) -> Texto con el nombre de la prenda en la que tiene interés.
* Campo: `item_interest_id` (bigint / opcional) -> Enlace directo (`FOREIGN KEY`) a la tabla `catalog_items(id)`. Esto te permite saber exactamente qué prenda del inventario quieren mediante relaciones de base de datos. Si se elimina la prenda, este campo se vuelve nulo para no romper el historial.
* Campo: `created_at` (timestamptz) -> Fecha y hora en que se envió la solicitud.

--------------------------------------------------------------------------------
2. CÓDIGO SQL PARA COPIAR Y PEGAR EN SUPABASE
--------------------------------------------------------------------------------

Copia todo este bloque de código y ejecútalo en la consola de Supabase (SQL Editor)
para crear las tablas, relaciones, restricciones, datos de prueba y políticas de
seguridad automáticamente.

```sql
-- 1. CREACIÓN DE LA TABLA DE PRENDAS (CATALOG_ITEMS)
CREATE TABLE public.catalog_items (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name varchar(255) NOT NULL,
    category varchar(50) NOT NULL,
    description text,
    price numeric(10, 2) NOT NULL DEFAULT 0.00,
    duration varchar(50) NOT NULL DEFAULT 'por día',
    img text NOT NULL,
    alt text,
    available boolean NOT NULL DEFAULT true,
    sizes varchar(255) NOT NULL,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL,
    
    -- Restricción para garantizar que solo existan estas categorías válidas
    CONSTRAINT chk_category CHECK (category IN ('ternos', 'vestidos', 'calzados'))
);

-- 2. CREACIÓN DE LA TABLA DE PROSPECTOS (RENTAL_LEADS)
CREATE TABLE public.rental_leads (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name varchar(255) NOT NULL,
    phone varchar(50) NOT NULL,
    event varchar(50) NOT NULL,
    date date NOT NULL,
    status varchar(50) NOT NULL DEFAULT 'Nuevo',
    item_interest varchar(255) NOT NULL DEFAULT 'Catálogo General',
    item_interest_id bigint REFERENCES public.catalog_items(id) ON DELETE SET NULL,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL,

    -- Restricciones para los tipos de evento y estados válidos
    CONSTRAINT chk_event CHECK (event IN ('boda', 'quince', 'graduacion', 'gala')),
    CONSTRAINT chk_status CHECK (status IN ('Nuevo', 'Contactado', 'Confirmado', 'Cancelado'))
);

-- Habilitamos RLS en ambas tablas por seguridad
ALTER TABLE public.catalog_items ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.rental_leads ENABLE ROW LEVEL SECURITY;

-- Políticas para catalog_items
-- Permite que cualquiera (incluso usuarios no logueados) vea las prendas del catálogo
CREATE POLICY "Permitir lectura pública de prendas" 
ON public.catalog_items FOR SELECT 
TO anon, authenticated 
USING (true);

-- Permite que solo usuarios autenticados (tu cuenta de administrador) puedan editar o agregar prendas
CREATE POLICY "Permitir control total de prendas solo a administradores" 
ON public.catalog_items FOR ALL 
TO authenticated 
USING (true) 
WITH CHECK (true);

-- Políticas para rental_leads
-- Permite que cualquier visitante inserte un nuevo lead (cuando llenan el formulario de contacto)
CREATE POLICY "Permitir que el público envíe consultas" 
ON public.rental_leads FOR INSERT 
TO anon, authenticated 
WITH CHECK (true);

-- Permite que solo los administradores autenticados puedan ver, actualizar o borrar leads
CREATE POLICY "Permitir control total de leads solo a administradores" 
ON public.rental_leads FOR ALL 
TO authenticated 
USING (true) 
WITH CHECK (true);
```

--------------------------------------------------------------------------------
3. PASO A PASO PARA SUBIR ESTO A SUPABASE
--------------------------------------------------------------------------------

1. Crea tu cuenta y proyecto:
   - Ve a https://supabase.com/ y crea una cuenta gratuita.
   - Presiona "New Project" (Nuevo Proyecto).
   - Ponle nombre a tu proyecto (ej. "MarketingDigital-AngelJashiel").
   - Elige una contraseña segura para tu base de datos y guárdala.
   - Elige la región más cercana a tus clientes (por ejemplo, "us-east-1" o
     "sa-east-1" para Sudamérica).
   - Haz clic en "Create new project". Espera unos 2 minutos a que se configure.

2. Ejecuta el script:
   - En el menú lateral izquierdo de Supabase, ve a la sección de "SQL Editor"
     (el icono es una hoja con el texto SQL o un símbolo `>_`).
   - Haz clic en "+ New query" (Nueva consulta) en la parte superior.
   - Copia todo el bloque de código SQL de la Sección 2 de este documento.
   - Pégalo en el editor de texto.
   - Presiona el botón verde "Run" (Ejecutar) que está abajo a la derecha del editor.
   - Deberías ver un mensaje que dice "Success. No rows returned" o similar, lo
     cual indica que las tablas se crearon correctamente y se insertaron las semillas.

3. Verifica tus datos:
   - En el menú lateral izquierdo, ve a "Table Editor" (el icono de tablas/cuadrícula).
   - Selecciona `catalog_items` y luego `rental_leads` para comprobar que las prendas y
     los prospectos están allí con la estructura correcta.

4. CÓMO VINCULARLO CON TU APLICACIÓN REACT
--------------------------------------------------------------------------------

Para usar esta base de datos en tu frontend de React:

1. Instala el cliente de Supabase en tu terminal de proyecto:
   `npm install @supabase/supabase-js`

2. Crea un archivo `src/lib/supabaseClient.ts` con el siguiente código:
   ```typescript
   import { createClient } from '@supabase/supabase-js';

   const supabaseUrl = import.meta.env.VITE_SUPABASE_URL || '';
   const supabaseAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY || '';

   export const supabase = createClient(supabaseUrl, supabaseAnonKey);
   ```

3. Agrega tus credenciales en un archivo `.env` en la raíz del proyecto:
   ```env
   VITE_SUPABASE_URL=https://tu-id-de-proyecto.supabase.co
   VITE_SUPABASE_ANON_KEY=tu-api-key-public-anon
   ```
   (Obtén estas llaves en Supabase -> Project Settings -> API).

4. Reemplaza el guardado en localStorage por consultas a Supabase en `App.tsx`:
   * Para obtener prendas:
     `const { data, error } = await supabase.from('catalog_items').select('*');`
   * Para insertar un lead:
     `const { data, error } = await supabase.from('rental_leads').insert([newLead]);`
   * Para cambiar disponibilidad de prenda:
     `await supabase.from('catalog_items').update({ available: false }).eq('id', id);`

5. Seguridad de Login (Supabase Auth):
   En lugar del usuario y clave estáticos (`admin`/`admin123`), puedes usar el
   servicio de autenticación integrado de Supabase para registrar e iniciar sesión
   como administrador oficial:
   `const { user, error } = await supabase.auth.signInWithPassword({ email, password });`
   Esto activará automáticamente el estado de "Usuario Autenticado" y permitirá
   que tu frontend pase las políticas RLS que creamos en el script SQL.
